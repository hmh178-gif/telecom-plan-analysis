# 📱 통신 3사 지원금·요금제 비교 분석 실습

> SKT·KT·LG U+의 휴대전화 지원금 및 요금제 데이터를 수집·정리하고,  
> 서로 다른 데이터 구조를 **휴대전화 모델 기준으로 매칭하여 비교 분석한 실무형 데이터 분석 실습**입니다.

- **프로젝트 형태:** 개인 실습
- **주요 도구:** AI 활용 데이터 수집·정리 · Python · HTML
- **분석 대상:** SKT · KT · LG U+
- **최종 결과물:** 지원금 인사이트 분석 HTML · 사용자 맞춤 통신사/요금제 추천 HTML

---

## 1. 실습 목적

통신사별로 서로 다른 형태로 제공되는 휴대전화 지원금 데이터를 하나의 기준으로 통합하고,  
요금제 데이터까지 결합하여 실제 사용자가 비교할 수 있는 형태의 결과물을 만드는 것을 목표로 했습니다.

주요 분석 질문은 다음과 같습니다.

- 동일한 휴대전화 모델에 대해 통신사별 지원금은 어떻게 다른가?
- 번호이동·기기변경·신규가입에 따라 지원금 차이가 있는가?
- 제조사 및 모델별로 지원금 패턴에 차이가 있는가?
- 지원금뿐 아니라 요금제까지 고려했을 때 실제 이용 비용은 어떻게 달라지는가?
- 사용자의 월 예산과 데이터 사용량에 따라 적합한 통신사와 요금제를 제안할 수 있는가?

---

## 2. 데이터 정리 및 매칭

통신 3사의 지원금 데이터는 사이트별로 상품명과 데이터 구조가 달라  
단순 병합이 아닌 **모델명 기준 데이터 매칭 과정**이 필요했습니다.

실습에서는 다음 기준을 적용했습니다.

- 휴대전화 상품만 분석 대상으로 제한
- 동일 모델·동일 용량 기준으로 데이터 통합
- 색상만 다른 동일 상품은 하나의 모델로 처리
- 모델명과 저장용량을 분리하여 비교
- 번호이동 · 기기변경 · 신규가입 조건 구분
- 요금제 조건 별도 관리
- 값이 없는 경우 `0`으로 처리하지 않고  
  **미표시 / 미수집 / 해당 없음** 등을 구분

현업 데이터는 처음부터 서로 매칭되도록 만들어지는 경우가 드물기 때문에, 공통 기준값을 정하고 직접 데이터 구조를 통일하는 과정이 중요하다는 점을 확인했습니다.

---

## 3. 데이터 검증

AI를 활용해 데이터를 수집했지만 결과를 그대로 사용하지 않고  
통신사별 원본 자료와 비교하며 검증했습니다.

특히 데이터가 비어 있는 경우에는 다음 상황을 구분했습니다.

- 실제 해당 항목이 존재하지 않는 경우
- 항목은 존재하지만 값이 비어 있는 경우
- 원본에는 값이 있지만 AI가 수집하지 못한 경우

이를 통해 **결측값을 단순히 0으로 처리하지 않고 데이터의 상태 자체를 구분하는 것이 중요**하다는 점을 학습했습니다.

---

## 4. 통신 3사 지원금 비교 분석

정리된 통합 데이터를 활용하여  
휴대전화 모델과 가입유형별로 SKT·KT·LG U+의 지원금을 비교했습니다.

분석에서는 단순히 지원금의 평균이나 최대값만 비교하지 않고,

- 통신사별 지원금 수준
- 제조사별 지원금 차이
- 모델별 지원금 편차
- 가입유형에 따른 차이

등을 함께 살펴보고, 주요 결과가 한눈에 보이도록 **1페이지 HTML 분석 보고서**로 구성했습니다.

---

## 5. 요금제 데이터 결합

지원금만으로 실제 이용 비용을 판단하기 어렵기 때문에  
통신 3사의 요금제 데이터를 추가로 결합했습니다.

비교 과정에서는 다음 요소를 함께 고려했습니다.

- 월 요금
- 데이터 제공량
- 공시지원금
- 선택약정 할인
- 가입유형
- 휴대전화 출고가
- 예상 월 납부액
- 예상 총 비용

단순 지원금 비교에서 끝나는 것이 아니라,  
**지원금 + 요금제를 결합해 사용자가 실제 부담하는 비용을 비교**하는 방향으로 분석을 확장했습니다.

## 6. 사용자 맞춤 통신사·요금제 추천

최종 결과물에서는 사용자가 조건을 직접 선택할 수 있도록  
반응형 HTML 형태의 추천 화면을 제작했습니다.

사용자는 다음 조건을 선택할 수 있습니다.

- 휴대전화 모델
- 저장용량
- 가입유형
- 월 예산
- 데이터 사용량
- 중요하게 생각하는 기준
- 이용할 요금제

선택 조건에 따라 각 통신사의

- 지원금
- 요금제
- 예상 월 요금
- 예상 총비용

을 비교하고, 조건에 적합한 통신사·요금제를 확인할 수 있도록 구성했습니다.

또한 요금제를 변경하면 예상 월 요금과 총비용도 함께 변경되도록 구현했습니다.

## 8. 실습을 통해 배운 점

### ① 데이터 분석에서 매칭 기준이 중요하다

서로 다른 출처의 데이터를 결합할 때는 단순히 비슷한 이름을 연결하는 것이 아니라  
**어떤 단위로 데이터를 비교할 것인지 먼저 정의해야 한다**는 점을 학습했습니다.

예를 들어 동일한 휴대전화라도 저장용량이나 색상에 따라 상품명이 달라질 수 있기 때문에  
분석 목적에 맞는 기준을 먼저 결정해야 했습니다.

### ② AI 결과는 반드시 검증해야 한다

AI를 데이터 수집과 정리에 활용할 수 있지만,  
`값이 없음`과 `수집 실패`를 AI가 잘못 판단할 수 있음을 직접 확인했습니다.

따라서 AI를 결과 생성 도구로만 사용하기보다  
**수집 → 검증 → 수정 → 재분석** 과정에 활용해야 한다는 점을 학습했습니다.

### ③ 프롬프트에서도 데이터 처리 기준을 명확하게 정의해야 한다

최종 실습에서는 처음부터 다음 내용을 구체적으로 지정했습니다.

- 분석 대상
- 포함·제외 범위
- 중복 처리 방법
- 가입유형 구분
- 빈값 처리 방식
- 작업 순서
- 최종 결과물 형태

이 과정을 통해 모호한 요청보다 **작업 조건과 검증 기준을 구조화한 프롬프트가 더 안정적인 결과를 만든다**는 점을 확인했습니다.

## 9. 최종 개선 사항

첫 실습 결과를 기반으로 동일한 분석을 다시 수행하면서 다음 부분을 개선했습니다.

- 색상만 다른 동일 상품의 중복 제거
- 단일 용량 모델 처리 기준 명확화
- 통신사별 가입유형 데이터 범위 통일
- 빈값 처리 규칙 명시
- 작업 순서를 사전에 고정
- 모델명과 저장용량 선택 분리
- 월 예산 입력 단위 개선
- 요금제 변경에 따른 예상 비용 실시간 반영
- 최종 인사이트가 한눈에 보이도록 HTML 구조 및 디자인 개선

이를 통해 첫 결과물을 단순히 수정하는 것이 아니라,  
**분석 과정에서 발견한 문제를 다음 작업의 데이터 처리 규칙으로 반영하는 방식**을 연습했습니다.
